Visão geral

O Claude Code roda numa máquina que não desliga, e você conversa com ele pelo celular, pelo navegador, pelo terminal e pelo VS Code. Este guia ajuda você a escolher onde essa máquina fica e leva você até a primeira sessão aberta pelo celular.

Como funciona

O serviço do Remote Control liga para o claude.ai de dentro da máquina. Nenhuma porta precisa abrir para o celular funcionar.

Na máquina, um serviço mantém o claude remote-control sempre de pé. Ele se conecta ao claude.ai por uma conexão de saída e abre uma sessão nova sempre que você pede pelo app, até 32 ao mesmo tempo. O terminal e o VS Code entram por SSH, como em qualquer servidor.

Qual escolher

  • Só GitHub e pacotes públicos, sem bypass? Comece pela nuvem da Anthropic. Não há máquina para manter.
  • Quer custo zero e uma máquina sua? Oracle com Pay As You Go. Na conta Pay As You Go, o que cabe no Always Free não é cobrado, e a Oracle não recolhe a VM por ociosidade.
  • Já tem uma VPS com folga rodando outras coisas? Um container LXD nela sai de graça e não mistura o agente com os outros serviços.
  • Prefere pagar, ou a Oracle está sem capacidade na sua região? Uma VPS dedicada num provedor comum.

Tamanho da máquina

Medimos com 2 núcleos e 7 GB de memória, num projeto Next.js com Postgres em Docker. A suíte inteira de testes de tela levou 32 minutos. Com menos de 4 GB, o build de um app web e o navegador dos testes disputam memória. Cada sessão parada do Claude Code ocupou de 200 a 500 MB, e a página Limites de memória dá a conta do teto das sessões.

Troque os nomes de exemplo

Os comandos usam três nomes de exemplo. Troque voce pelo seu usuário, agente pelo nome da máquina e projeto pela pasta do repo na máquina. Escolha os três antes de começar, porque eles se repetem em várias páginas.

ARM ou x86

A Oracle grátis é ARM. Confira se as imagens Docker e os binários do projeto têm versão linux/arm64. Imagem Docker que roda num Mac com Apple Silicon já é linux/arm64 e serve. Binário que o npm ou o pip baixam no Mac é para macOS e não prova nada. Se o seu deploy já roda em ARM, o projeto roda.

Como funciona a nuvem da Anthropic

No Claude Code na web, cada sessão roda numa VM que a Anthropic cria e mantém. Não existe máquina para você configurar, e a sessão continua com o seu computador desligado.

O caminho de uma sessão

  1. Você pedePelo claude.ai/code, pela aba Code do app do Claude, ou com claude --cloud "tarefa" no terminal.
  2. A VM nasceNo navegador e no app, você escolhe o repo e o branch. Pelo terminal, o --cloud clona o branch atual do GitHub. Commit sem push não chega.
  3. O ambiente preparaRoda o setup script do ambiente, ou reaproveita o disco guardado da última vez.
  4. O Claude trabalhaEdita, roda testes, sobe serviços com Docker e devolve um branch. O PR sai pela própria sessão.
  5. Você continua de onde quiserPelo app, pelo navegador, ou no terminal com claude --teleport, que traz a sessão e o branch dela.

O que já vem na VM

Docker, docker compose, PostgreSQL 16 e Redis 7, além das linguagens e gerenciadores de pacote comuns. O PostgreSQL e o Redis vêm parados, e o Claude sobe quando você pede.

O que configurar

  1. Conecte o GitHubNo primeiro acesso ao claude.ai/code. Repo público já funciona. Para repo privado, instale o app do Claude no GitHub da conta dona do repo. Pelo terminal, /web-setup manda o token do seu gh para a conta. No Team e no Enterprise, o /web-setup só aparece se um Owner ligar o Quick web setup.
  2. Confira o ambiente e a redeO primeiro acesso cria o ambiente Default, com rede Trusted, ou pede para você criar. Para mudar, use o seletor de ambiente do claude.ai/code. Trusted libera registries de pacote, GitHub e Docker Hub. Custom usa só a sua lista de domínios, e soma a do Trusted se você marcar a opção. Full libera qualquer domínio, e None corta tudo.
  3. Ponha as variáveis de ambienteNo formato .env. Todo mundo que usa o ambiente lê os valores. No Pro e no Max, guarde chave de API em API credentials, e a sessão usa a chave sem enxergá-la.
  4. Escreva o setup scriptInstale as dependências e rode docker compose pull. Se ele termina em uns 5 minutos, a Anthropic guarda o disco, e as próximas sessões começam prontas. O disco guardado vale uns 7 dias e guarda arquivos, não processos, então banco e compose sobem de novo a cada sessão.

Os limites

  • A VM pausa depois de alguns minutos sem atividade e pode ser recolhida. Reabrir a sessão devolve a conversa, mas não o que rodava em segundo plano.
  • Não existe modo bypass. Os modos são Accept edits, Plan e Auto, em que um classificador revisa cada ação.
  • A sessão não alcança o que não tem endereço público, como um banco atrás de túnel SSH.
  • Para devolver commit e PR, o repo precisa estar no GitHub.
  • Está nos planos Pro, Max e Team, e no Enterprise com assento premium ou Chat + Claude Code. A VM não é cobrada à parte, e as sessões gastam a cota da conta.

Quando ela basta

Quando o projeto só precisa de GitHub, pacotes públicos e serviços que sobem em Docker na própria VM, e você aceita aprovar ou deixar o modo Auto aprovar as ações. Se algum desses falha, use uma máquina sua com Remote Control, começando pela Oracle.

Ambiente self-hosted

Organizações Team e Enterprise podem fazer as sessões da nuvem rodarem em máquinas próprias, com um runner. Está em beta, um Owner liga em Admin settings, Cloud environments, e a instalação está no quickstart oficial. Este guia não cobre esse caminho.

1. REGRAS DE CONDUTA
======================================================================

Faça:
- Trabalhe em passos curtos. Antes de cada passo, diga em uma linha o que vai fazer e por quê. Depois, mostre a saída que prova que funcionou.
- Rode você mesmo os comandos que não pedem resposta. Nos remotos, use ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new <host> 'bash -lc "..."' com timeout. Comando que passa de 5 minutos, como uma suíte de testes, roda num tmux da máquina com a saída num log, e você acompanha pelo log.
- Comando que pede resposta no terminal (logins, ssh-add, o primeiro claude remote-control, tailscale up, sudo com senha) eu rodo. Me entregue a linha pronta para colar, diga em qual terminal ela roda (WSL, PowerShell, macOS ou dentro da máquina), o que vai aparecer, e espere eu dizer que terminei.
- O que acontece num site (criar conta, clicar num console, digitar um código) eu faço. Diga onde clicar e o que preencher, com o link, e espere. Peça um print quando precisar conferir.
- Mantenha ~/claude-always-on/progresso.md atualizado depois de cada passo: caminho, valores escolhidos, passos feitos e o próximo. Nunca grave senha, token ou chave privada ali.
- Se a conversa for compactada ou recomeçar, leia ~/claude-always-on/progresso.md antes de qualquer outra coisa e retome do próximo passo.
- Os roteiros usam valores de exemplo entre <>. Troque pelos da entrevista ou da medição, e mostre todos no plano antes de usar: <usuario>, <maquina>, <host> (o Host da VPS no meu ~/.ssh/config, no R3), <ip>, <repo> (o do projeto, no formato dono/nome), <repo-dotfiles>, <pasta> (a pasta do repo na máquina), <interface>, <subrede>, <gateway> (o .1 da subrede), <ip-container> (o .10 da subrede), <pool>, <memoria>, <flags>, <swap>, <teto>, <alto> e <swap-agentes>. Os números dos roteiros (192.168.200.x, 60GiB, 6GiB, 5G, 4608M) são exemplo e nunca entram como estão.
- Quando um passo falhar, investigue, conserte e prove de novo antes de avançar. Consulte a seção 7 quando o sintoma bater.

Não faça:
- Não junte os passos num script de instalação. Execute um bloco por vez e mostre a saída.
- Não copie ~/.claude/.credentials.json nem ~/.claude.json entre máquinas. Cada máquina faz o próprio login. O token de renovação gira, e a primeira máquina que renovar derruba a outra.
- Não mostre senha, token ou chave privada na tela, nem grave em arquivo, log ou commit. Para ler um .env, use só os nomes (cut -d= -f1 .env) e, das URLs, só host e porta. Nunca rode cat, head ou grep que mostre a linha inteira de um .env.
- Não leve para a máquina nova segredo que o agente não usa, como chave root de nuvem ou a chave SSH pessoal que abre outros servidores.
- Na minha máquina, você pode escrever em ~/claude-always-on/, acrescentar blocos ao ~/.ssh/config e trocar o User dos blocos que você criou, criar chave nova em ~/.ssh sem sobrescrever nenhuma, e deixar o ssh gravar no known_hosts. No WSL, vale o mesmo em /mnt/c/Users/<eu>/.ssh. Para qualquer outra coisa, pergunte.
- Num host que já roda outros serviços (R3): não reinicie o host, o Docker nem serviço existente; não rode netfilter-persistent save; não ligue ufw; não mude o hostname; não instale nada além do LXD, e só com a minha confirmação; crie swap no host só com a minha confirmação, porque os serviços dele passam a usar o mesmo swap. Meça a resposta dos serviços antes e depois de cada mudança de rede e me mostre os dois resultados.
- Não rode lxc num host sem me avisar antes: no Ubuntu 24.04, o primeiro lxc instala o snap do LXD.
- No R3, tudo dentro do container roda por sudo lxc exec <maquina> -- ..., nunca num shell aberto com bash. Um usermod ou um rm do sudoers rodado no host por engano renomeia o usuário dele e tira o sudo.
- Não ligue o ufw sem antes liberar o SSH, e não ligue o ufw numa VM da Oracle, que já filtra com iptables e com a security list da VCN.
- Não abra porta para a internet além da 22. O Remote Control não precisa de porta aberta.
- Não ponha defaultMode "bypassPermissions" em .claude/settings.json ou .claude/settings.local.json esperando que funcione: o Claude Code ignora esse valor vindo do projeto. O bypass vai como flag depois de remote-control.
- Não ponha flags globais antes do subcomando, como claude --dangerously-skip-permissions remote-control. O servidor recusa.
- Nunca rode chezmoi init --apply. Veja C4.
- Nunca rode pelo seu shell um comando que abre tela cheia, como claude agents sem --json: ele trava.
- Na Oracle, não passe de 2 OCPU e 12 GB somando todas as VMs ARM, de 200 GB somando todos os discos, nem de 5 backups de volume, e não ligue política de backup no volume de boot. Acima disso a conta Pay As You Go cobra.
- Não reinicie a máquina remota, não apague arquivo, VM ou disco, e não rode comando destrutivo sem me pedir confirmação na hora.

RE_LIMITE = re.compile(r"resets (?P<quando>.+?)\s*\((?P<fuso>[^)]+)\)")
RE_HORA = re.compile(r"(?P<h>\d{1,2})(?::(?P<m>\d{2}))?\s*(?P<ap>am|pm)", re.I)
RE_DATA = re.compile(r"(?P<mes>[A-Z][a-z]{2})[a-z]*\.?\s+(?P<dia>\d{1,2})")
MESES = "Jan Feb Mar Apr May Jun Jul Aug Sep Oct Nov Dec".split()


def log(msg):
    print(msg, flush=True)


def data(ts):
    return datetime.fromisoformat(ts.replace("Z", "+00:00"))


def texto_de(entrada):
    conteudo = entrada.get("message", {}).get("content")
    if isinstance(conteudo, list):
        return " ".join(p.get("text", "") for p in conteudo if isinstance(p, dict))
    return conteudo if isinstance(conteudo, str) else ""


def horario_de_volta(mensagem, parada):
    """Lê "resets 9:50am (UTC)" ou "resets Oct 7, 5pm (UTC)". Devolve (horário, lido)."""
    achado = RE_LIMITE.search(mensagem)
    hora = RE_HORA.search(achado.group("quando")) if achado else None
    if not hora:
        return parada + timedelta(hours=5), False
    try:
        fuso = ZoneInfo(achado.group("fuso").strip())
    except Exception:
        return parada + timedelta(hours=5), False
    h = int(hora.group("h")) % 12 + (12 if hora.group("ap").lower() == "pm" else 0)
    m = int(hora.group("m") or 0)
    local = parada.astimezone(fuso)
    dia = RE_DATA.search(achado.group("quando"))
    if dia and dia.group("mes") in MESES:
        volta = local.replace(month=MESES.index(dia.group("mes")) + 1, day=int(dia.group("dia")),
                              hour=h, minute=m, second=0, microsecond=0)
        if volta < local - timedelta(days=1):
            volta = volta.replace(year=volta.year + 1)
    else:
        volta = local.replace(hour=h, minute=m, second=0, microsecond=0)
        if volta <= local:
            volta += timedelta(days=1)
    return volta.astimezone(timezone.utc), True


def parada_por_limite(historico):
    """Devolve a última fala se ela for o erro de limite, ou None."""
    ultima = None
    with open(historico, encoding="utf-8", errors="replace") as f:
        for linha in f:
            try:
                e = json.loads(linha)
            except ValueError:
                continue
            if e.get("type") in ("user", "assistant") and not e.get("isSidechain"):
                ultima = e
    if ultima and ultima.get("isApiErrorMessage") and ultima.get("error") == "rate_limit":
        return ultima
    return None


def pontas(arquivo):
    """Primeiro e último timestamp de um histórico de subagente."""
    primeiro = ultimo = None
    with open(arquivo, "rb") as f:
        for linha in f:
            ts = json.loads(linha).get("timestamp") if b'"timestamp"' in linha else None
            if ts:
                primeiro = ts
                break
        f.seek(max(0, os.path.getsize(arquivo) - 65536))
        for linha in f.read().splitlines():
            try:
                ts = json.loads(linha).get("timestamp")
            except ValueError:
                continue
            ultimo = ts or ultimo
    return primeiro and data(primeiro), ultimo and data(ultimo)


def subagentes(historico, parada):
    pasta = historico.with_suffix("") / "subagents"
    abertos = ativos = 0
    for arquivo in pasta.glob("agent-*.jsonl"):
        inicio, fim = pontas(arquivo)
        if not inicio:
            continue
        if parada - JANELA_SUBAGENTES <= inicio <= parada:
            abertos += 1
        if inicio <= parada and fim and fim >= parada - JANELA_ATIVOS:
            ativos += 1
    return abertos, ativos


def detectar(projetos, pastas, agora, janela):
    for pasta in pastas:
        for historico in sorted((projetos / pasta).glob("*.jsonl")):
            idade = agora.timestamp() - historico.stat().st_mtime
            if janela and idade > janela.total_seconds():
                continue
            e = parada_por_limite(historico)
            if not e:
                continue
            parada = data(e["timestamp"])
            mensagem = texto_de(e).strip()
            volta, lido = horario_de_volta(mensagem, parada)
            abertos, ativos = subagentes(historico, parada)
            yield {
                "sessao": historico.stem, "pasta": pasta, "historico": str(historico),
                "parada": parada.isoformat(), "volta": volta.isoformat(), "volta_lida": lido,
                "mensagem_limite": mensagem, "subagentes": abertos, "ativos": ativos,
            }


def processo_vivo(sessao):
    for arquivo in SESSOES.glob("*.json"):
        try:
            s = json.loads(arquivo.read_text())
        except (ValueError, OSError):
            continue
        if s.get("sessionId") != sessao:
            continue
        try:
            inicio = Path(f"/proc/{s['pid']}/stat").read_text().rsplit(")", 1)[1].split()[19]
        except (OSError, IndexError, KeyError):
            continue
        if inicio == str(s.get("procStart")):
            return s
    return None


def entregue(historico, parada, marca):
    """A marca aparece no histórico depois da parada."""
    with open(historico, encoding="utf-8", errors="replace") as f:
        return any(marca in linha for linha in f if '"timestamp"' in linha
                   and json.loads(linha).get("timestamp", "") > parada)

Onde hospedar

Container numa VPS compartilhada

Se você já tem uma VPS com folga rodando outros serviços, um container LXD dá ao agente um Linux próprio, com Docker próprio. O docker ps dele não mostra os seus serviços, e limites de memória, CPU e disco protegem o resto.

Não faça no host

Não rode os passos de Preparar a máquina no host. Eles mudam o hostname e ligam o ufw, que bloqueia os serviços. Não rode netfilter-persistent save. Não reinicie o host nem o Docker. Meça os serviços antes e depois de cada mudança de rede.

As quatro primeiras regras deixam o container receber IP e DNS do host e mais nada do host. As duas últimas deixam ele sair para a internet só pela interface de saída. Troque enp0s6 por ela, a do ip route | grep default. Sem Docker no host, troque DOCKER-USER por FORWARD nas duas últimas regras. Cada regra entra no topo da lista, então o REJECT vem primeiro no arquivo e os ACCEPT ficam acima dele.
bash, no host
sudo tee /usr/local/sbin/lxd-firewall.sh > /dev/null <<'EOF'
#!/bin/sh
set -e
regra() { iptables -C "$@" 2>/dev/null || iptables -I "$@"; }
regra INPUT -i lxdbr0 -j REJECT
regra INPUT -i lxdbr0 -p udp --dport 67 -j ACCEPT
regra INPUT -i lxdbr0 -p udp --dport 53 -j ACCEPT
regra INPUT -i lxdbr0 -p tcp --dport 53 -j ACCEPT
regra DOCKER-USER -i lxdbr0 -o enp0s6 -j ACCEPT
regra DOCKER-USER -i enp0s6 -o lxdbr0 -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
EOF
sudo chmod 755 /usr/local/sbin/lxd-firewall.sh

sudo tee /etc/systemd/system/lxd-firewall.service > /dev/null <<'EOF'
[Unit]
After=netfilter-persistent.service docker.service snap.lxd.daemon.service
PartOf=docker.service

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/lxd-firewall.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target docker.service
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now lxd-firewall

Remote Control como serviço

No modo servidor, claude remote-control fica esperando e abre uma sessão nova sempre que você pede pelo app, até 32 ao mesmo tempo. O systemd mantém ele de pé e o devolve depois de um reboot.

Primeira vez, à mão

Rode, na pasta do repo, o mesmo comando que o serviço vai rodar. Responda y à confiança na pasta e ao Remote Control, aceite o aviso do bypass se aparecer, e saia com Ctrl+C. Sem bypass, troque bypassPermissions por default aqui e no script. Com bypass, rode antes também claude --dangerously-skip-permissions uma vez na pasta, aceite o aviso e saia com /exit.

bash, na máquina
cd ~/projeto && claude remote-control --spawn same-dir --permission-mode bypassPermissions
Sem este passo

O serviço fica ativo e parado numa pergunta de primeira vez, e nenhuma sessão aparece no app.

O script

O laço existe porque o servidor sai sozinho depois de uns 10 minutos sem rede.

bash, na máquina
mkdir -p ~/.local/bin && cat > ~/.local/bin/agente-rc <<'EOF'
#!/bin/sh
cd "$HOME/projeto" || exit 1
while true; do
    claude remote-control --spawn same-dir --permission-mode bypassPermissions
    sleep 10
done
EOF
chmod 755 ~/.local/bin/agente-rc

O serviço

Ele roda o script num tmux de socket próprio. No socket padrão, o tmux que você abre pelo SSH nasceria dentro do serviço e morreria a cada reinício dele.

bash, na máquina
sudo tee /etc/systemd/system/agente-rc.service > /dev/null <<'EOF'
[Unit]
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=forking
User=voce
ExecStart=/usr/bin/tmux -L rc new-session -d -s rc "bash -lic agente-rc"

RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now agente-rc

Troque bash -lic por zsh -lic se o seu shell de login é zsh. O -l põe o claude no PATH, e o -i carrega o .bashrc ou o .zshrc, onde nvm, pyenv e afins põem o deles. O painel do servidor abre com tmux -L rc attach -t rc.

Limites de memória

Sem limite, um comando pesado de uma sessão enche a memória da máquina, e as outras sessões e o SSH param junto. Com swap e um teto para as sessões, só o comando pesado morre, e um servidor de resgate com 512 MB reservados continua abrindo sessão pelo celular. No mesmo grupo do resgate, um job retoma as sessões que pararam por limite de uso.

Na nossa montagem, num container com 2 núcleos e 7 GB e sem swap, um typecheck com dois tsc de 1 GB cada levou a memória ao limite. Cada conexão SSH passou de 1 segundo para 20 a 77 segundos, e as sessões do app pararam de responder. Esta página monta o swap, o teto das sessões, o servidor de resgate e os limites escritos onde as sessões leem.

Swap

Com o swap ligado e o typecheck ainda rodando, a pressão de memória da nossa máquina caiu de 45% para 32%, e 637 MB foram para o swap. Antes, confira com findmnt -no FSTYPE / que o disco é ext4, onde testamos, e com df -h / que sobram pelo menos 8 GB. Em btrfs, o arquivo de swap precisa de outro procedimento. Usamos 8 GB num host de 12 GB.

bash, na máquina
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

O teto das sessões

O serviço do Remote Control entra num grupo do systemd com teto de memória, e tudo o que as sessões dele disparam entra junto: MCP, testes, build e navegador. Passou do alto, o grupo fica lento e empurra memória para o swap. Bateu no teto, o kernel mata o maior processo do grupo, que quase sempre é o comando pesado, e a sessão que o rodou continua viva.

As duas últimas linhas mostram 0::/agentes.slice/agente-rc.service e OOMPolicy=continue. Sem o OOMPolicy=continue, vale o padrão do systemd, stop: quando o kernel mata um processo do serviço, o systemd derruba o servidor inteiro, com todas as sessões. Testamos os dois numa unidade de teste. Com stop, ela terminou em falha, e com continue, só o processo pesado morreu. O serviço só muda de grupo ao reiniciar, e o reinício derruba as sessões abertas. Na nossa montagem, as que estavam no meio de uma tarefa voltaram sozinhas em menos de 1 minuto.

Com mais de um projeto, cada um com o seu serviço do Remote Control, ponha o mesmo drop-in em cada serviço e acrescente nele um teto próprio, para um projeto não ocupar o grupo inteiro. Usamos MemoryHigh=3G e MemoryMax=3584M em cada um de dois projetos, dentro do teto de 5 GB.

Retomar as sessões paradas por limite de uso

Quando a conta bate o limite de uso, a sessão que estava trabalhando para com You've hit your session limit · resets 9:50am (UTC) e fica parada até alguém escrever nela. Um job do systemd confere os históricos a cada 5 minutos. Depois do horário de volta, ele manda uma mensagem a cada sessão parada, uma vez por limite. A mensagem diz que a sessão estourou o limite e quantos subagentes ela abriu nas 5 horas antes da parada, pede que ela confira se foi ela quem gastou, e pede que siga sem subagentes em paralelo e com cautela de tokens.

O job roda no resgate.slice, com teto próprio de 512 MB, e não disputa memória com as sessões do projeto. Ele só gasta token quando retoma uma sessão, com um turno curto de Haiku por sessão. Na nossa máquina, a rodada sem sessão parada levou 0,4 s de CPU, e o mensageiro chegou a 284 MB.

Como ele decide

  • Parada por limite: a última fala da conversa principal, em ~/.claude/projects/<pasta>/<id>.jsonl, é uma linha com "error": "rate_limit". Se alguém já escreveu na sessão depois disso, ela não entra.
  • Horário de volta: lido do próprio texto do limite, no fuso entre parênteses. Sem texto legível, vale a parada mais 5 horas.
  • Subagentes: um arquivo por subagente em <id>/subagents/. Na nossa máquina, a sessão que estourou o limite tinha aberto 26 nas 5 horas anteriores, com 9 rodando na hora da parada. As outras abriram de 1 a 6.
  • Entrega: o processo vivo da sessão aparece em ~/.claude/sessions/<pid>.json, com o nome dela. Um claude -p mensageiro em bypass manda o texto com SendMessage. Uma sessão em bypass retém a mensagem de um remetente que não está em bypass, então o mensageiro também roda em bypass.
  • Uma vez por limite: o estado fica em ~/.local/state/retomar-limite/estado.json, e a entrega só conta quando o texto aparece no histórico da sessão.
Sessões sem bypass

Testamos só com sessões em bypass. Pela documentação, uma sessão que pede permissão retém a mensagem de um remetente em bypass. Sem bypass, tire --permission-mode bypassPermissions da função enviar, ponha --allowedTools SendMessage e repita o teste abaixo antes de ligar o timer.

Grave o script. Com mais de um projeto, acrescente a pasta de cada um em PASTAS, relativa à sua pasta pessoal:

bash, na máquina
cat > ~/.local/bin/retomar-limite <<'EOF'
#!/usr/bin/env python3
"""Retoma as sessões do Remote Control que pararam por limite de uso da conta.

Roda pelo retomar-limite.timer. Lê os históricos das pastas em PASTAS, acha a sessão cuja
última fala é o erro de limite, espera o horário de volta e manda uma mensagem nela
por um `claude -p` mensageiro, que usa SendMessage. Cada limite é retomado uma vez.
"""

import argparse
import fcntl
import json
import os
import re
import subprocess
import sys
import time
from datetime import datetime, timedelta, timezone
from pathlib import Path
from zoneinfo import ZoneInfo

CASA = Path.home()
PROJETOS = CASA / ".claude" / "projects"
SESSOES = CASA / ".claude" / "sessions"
PASTAS = [re.sub(r"[^A-Za-z0-9]", "-", str(CASA / p)) for p in ("projeto", "resgate")]
ESTADO = CASA / ".local" / "state" / "retomar-limite" / "estado.json"

MARGEM = timedelta(minutes=2)
JANELA_SUBAGENTES = timedelta(hours=5)
JANELA_ATIVOS = timedelta(minutes=5)
TENTATIVAS = 3

MENSAGEM = (
    "Esta sessão parou às {hora_parada} UTC porque a conta bateu o limite de uso "
    '("{mensagem_limite}"). O limite voltou às {hora_volta} UTC. Antes de continuar, '
    "confira se foi esta sessão que gastou o limite. Nas 5 horas antes da parada ela abriu "
    "{n_subagentes} subagentes, e {n_ativos} estavam rodando na hora da parada. Se foi aqui, "
    "por exemplo por ter disparado 10 ou 15 subagentes em paralelo, não retome do mesmo jeito. "
    "Siga a tarefa sem subagentes em paralelo, com no máximo um por vez e só quando uma pesquisa "
    "exigir. Se não foi aqui, outra sessão em paralelo pode ter consumido o limite, e está tudo "
    "certo. Nos dois casos, siga com cautela de tokens: leia trechos em vez de arquivos inteiros "
    "e corte saída longa. Depois continue de onde parou. [{marca}]"
)

MENSAGEIRO = """Você é só um mensageiro. Faça isto e nada mais:
1. Use a ferramenta SendMessage com to="{nome}" e, como message, o texto entre as linhas INICIO e FIM, exatamente igual, sem mudar uma letra.
2. Se a ferramenta recusar ou não achar a sessão, não tente outro caminho.
3. Responda numa linha só: ENVIADO, ou FALHOU seguido do motivo.

INICIO
{texto}
FIM"""

RE_LIMITE = re.compile(r"resets (?P<quando>.+?)\s*\((?P<fuso>[^)]+)\)")
RE_HORA = re.compile(r"(?P<h>\d{1,2})(?::(?P<m>\d{2}))?\s*(?P<ap>am|pm)", re.I)
RE_DATA = re.compile(r"(?P<mes>[A-Z][a-z]{2})[a-z]*\.?\s+(?P<dia>\d{1,2})")
MESES = "Jan Feb Mar Apr May Jun Jul Aug Sep Oct Nov Dec".split()


def log(msg):
    print(msg, flush=True)


def data(ts):
    return datetime.fromisoformat(ts.replace("Z", "+00:00"))


def texto_de(entrada):
    conteudo = entrada.get("message", {}).get("content")
    if isinstance(conteudo, list):
        return " ".join(p.get("text", "") for p in conteudo if isinstance(p, dict))
    return conteudo if isinstance(conteudo, str) else ""


def horario_de_volta(mensagem, parada):
    """Lê "resets 9:50am (UTC)" ou "resets Oct 7, 5pm (UTC)". Devolve (horário, lido)."""
    achado = RE_LIMITE.search(mensagem)
    hora = RE_HORA.search(achado.group("quando")) if achado else None
    if not hora:
        return parada + timedelta(hours=5), False
    try:
        fuso = ZoneInfo(achado.group("fuso").strip())
    except Exception:
        return parada + timedelta(hours=5), False
    h = int(hora.group("h")) % 12 + (12 if hora.group("ap").lower() == "pm" else 0)
    m = int(hora.group("m") or 0)
    local = parada.astimezone(fuso)
    dia = RE_DATA.search(achado.group("quando"))
    if dia and dia.group("mes") in MESES:
        volta = local.replace(month=MESES.index(dia.group("mes")) + 1, day=int(dia.group("dia")),
                              hour=h, minute=m, second=0, microsecond=0)
        if volta < local - timedelta(days=1):
            volta = volta.replace(year=volta.year + 1)
    else:
        volta = local.replace(hour=h, minute=m, second=0, microsecond=0)
        if volta <= local:
            volta += timedelta(days=1)
    return volta.astimezone(timezone.utc), True


def parada_por_limite(historico):
    """Devolve a última fala se ela for o erro de limite, ou None."""
    ultima = None
    with open(historico, encoding="utf-8", errors="replace") as f:
        for linha in f:
            try:
                e = json.loads(linha)
            except ValueError:
                continue
            if e.get("type") in ("user", "assistant") and not e.get("isSidechain"):
                ultima = e
    if ultima and ultima.get("isApiErrorMessage") and ultima.get("error") == "rate_limit":
        return ultima
    return None


def pontas(arquivo):
    """Primeiro e último timestamp de um histórico de subagente."""
    primeiro = ultimo = None
    with open(arquivo, "rb") as f:
        for linha in f:
            ts = json.loads(linha).get("timestamp") if b'"timestamp"' in linha else None
            if ts:
                primeiro = ts
                break
        f.seek(max(0, os.path.getsize(arquivo) - 65536))
        for linha in f.read().splitlines():
            try:
                ts = json.loads(linha).get("timestamp")
            except ValueError:
                continue
            ultimo = ts or ultimo
    return primeiro and data(primeiro), ultimo and data(ultimo)


def subagentes(historico, parada):
    pasta = historico.with_suffix("") / "subagents"
    abertos = ativos = 0
    for arquivo in pasta.glob("agent-*.jsonl"):
        inicio, fim = pontas(arquivo)
        if not inicio:
            continue
        if parada - JANELA_SUBAGENTES <= inicio <= parada:
            abertos += 1
        if inicio <= parada and fim and fim >= parada - JANELA_ATIVOS:
            ativos += 1
    return abertos, ativos


def detectar(projetos, pastas, agora, janela):
    for pasta in pastas:
        for historico in sorted((projetos / pasta).glob("*.jsonl")):
            idade = agora.timestamp() - historico.stat().st_mtime
            if janela and idade > janela.total_seconds():
                continue
            e = parada_por_limite(historico)
            if not e:
                continue
            parada = data(e["timestamp"])
            mensagem = texto_de(e).strip()
            volta, lido = horario_de_volta(mensagem, parada)
            abertos, ativos = subagentes(historico, parada)
            yield {
                "sessao": historico.stem, "pasta": pasta, "historico": str(historico),
                "parada": parada.isoformat(), "volta": volta.isoformat(), "volta_lida": lido,
                "mensagem_limite": mensagem, "subagentes": abertos, "ativos": ativos,
            }


def processo_vivo(sessao):
    for arquivo in SESSOES.glob("*.json"):
        try:
            s = json.loads(arquivo.read_text())
        except (ValueError, OSError):
            continue
        if s.get("sessionId") != sessao:
            continue
        try:
            inicio = Path(f"/proc/{s['pid']}/stat").read_text().rsplit(")", 1)[1].split()[19]
        except (OSError, IndexError, KeyError):
            continue
        if inicio == str(s.get("procStart")):
            return s
    return None


def entregue(historico, parada, marca):
    """A marca aparece no histórico depois da parada."""
    with open(historico, encoding="utf-8", errors="replace") as f:
        return any(marca in linha for linha in f if '"timestamp"' in linha
                   and json.loads(linha).get("timestamp", "") > parada)


def enviar(nome, texto, cwd):
    prompt = MENSAGEIRO.format(nome=nome, texto=texto)
    r = subprocess.run(
        ["claude", "-p", "--model", "haiku", "--permission-mode", "bypassPermissions",
         "--no-session-persistence", "--strict-mcp-config", "--tools", "SendMessage,ListAgents"],
        input=prompt, capture_output=True, text=True, timeout=300, cwd=cwd,
    )
    return (r.stdout.strip().splitlines() or [r.stderr.strip()[-200:]])[-1]


def main():
    p = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    p.add_argument("--detectar", action="store_true", help="só lista, sem estado e sem mensagem")
    p.add_argument("--projetos", type=Path, default=PROJETOS)
    p.add_argument("--pasta", action="append", help="pasta de projetos, repetível")
    p.add_argument("--estado", type=Path, default=ESTADO)
    p.add_argument("--agora", help="horário ISO, para teste")
    p.add_argument("--horas", type=float, default=24, help="idade máxima do histórico, 0 = todos")
    a = p.parse_args()

    agora = data(a.agora) if a.agora else datetime.now(timezone.utc)
    janela = timedelta(hours=a.horas) if a.horas else None
    achados = list(detectar(a.projetos, a.pasta or PASTAS, agora, janela))

    if a.detectar:
        for s in achados:
            log(json.dumps(s, ensure_ascii=False))
        log(f"{len(achados)} sessões paradas por limite")
        return

    a.estado.parent.mkdir(parents=True, exist_ok=True)
    trava = open(a.estado.with_suffix(".lock"), "w")
    fcntl.flock(trava, fcntl.LOCK_EX)
    estado = json.loads(a.estado.read_text()) if a.estado.exists() else {}

    for s in achados:
        chave = f"{s['sessao']}@{s['volta']}"
        reg = estado.setdefault(chave, {**s, "situacao": "esperando", "tentativas": 0})
        marca = f"retomada-limite {s['sessao'][:8]} {s['volta'][:16]}"
        if reg["situacao"] in ("retomada", "desistiu"):
            continue
        if reg["tentativas"] and entregue(s["historico"], s["parada"], marca):
            reg["situacao"] = "retomada"
            log(f"{chave}: entrega confirmada no histórico")
            continue
        if agora < datetime.fromisoformat(s["volta"]) + MARGEM:
            if not reg.get("avisado"):
                log(f"{chave}: parada às {s['parada'][11:16]}, esperando o limite voltar")
                reg["avisado"] = True
            continue
        vivo = processo_vivo(s["sessao"])
        if not vivo:
            if reg["situacao"] != "sem processo":
                log(f"{chave}: sem processo vivo, retome pelo app")
            reg["situacao"] = "sem processo"
            continue
        if reg["tentativas"] >= TENTATIVAS:
            reg["situacao"] = "desistiu"
            log(f"{chave}: {TENTATIVAS} tentativas sem confirmação, desisti")
            continue
        texto = MENSAGEM.format(
            hora_parada=s["parada"][11:16], hora_volta=s["volta"][11:16],
            mensagem_limite=s["mensagem_limite"], n_subagentes=s["subagentes"],
            n_ativos=s["ativos"], marca=marca,
        )
        reg["tentativas"] += 1
        resposta = enviar(vivo["name"], texto, a.estado.parent)
        reg["resposta"] = resposta
        log(f"{chave}: mensageiro para {vivo['name']} respondeu {resposta}")
        for _ in range(12):
            if entregue(s["historico"], s["parada"], marca):
                reg["situacao"] = "retomada"
                log(f"{chave}: entrega confirmada no histórico")
                break
            time.sleep(5)
        a.estado.write_text(json.dumps(estado, ensure_ascii=False, indent=1))

    a.estado.write_text(json.dumps(estado, ensure_ascii=False, indent=1))


if __name__ == "__main__":
    sys.exit(main())

Provar que funciona

Confira cada item antes de deixar a máquina sozinha. Na nossa montagem, os testes, os servidores MCP e o modo de permissão pegaram defeito. Dias depois, foi a memória.

Segurança e custos

Uma máquina que trabalha sozinha 24 horas faz tudo o que as chaves dela permitem. Dê a ela só o necessário.

  • Dê ao agente só as chaves que ele usa, cada uma revogável sem afetar as suas.
  • O login do Claude na máquina vence. A sessão que dura mais que ele para de andar até um login novo, então renove quando o app parar de abrir sessão.
  • As sessões gastam a mesma cota da sua conta do Claude, seja na sua máquina, na Oracle ou na nuvem da Anthropic. Uma noite inteira de trabalho do agente consome o limite que seria seu de manhã.
  • Uma máquina com IP público recebe tentativas de login no SSH o tempo todo. Login por senha desligado e atualização automática são o mínimo, e o Tailscale tira a porta da internet.
  • Num host compartilhado, um build pesado do agente deixa os outros serviços mais lentos. O peso de CPU dá prioridade ao host, mas não zera a disputa.
  • Um reboot interrompe as sessões em segundo plano. Por até 48 horas, elas aparecem como failed e voltam de onde pararam quando você entra nelas. Depois disso aparecem como stopped.
  • Na Oracle Pay As You Go, nada é cobrado dentro da cota, e o orçamento com alerta avisa se algo sair dela. Uma VPS paga custa a mensalidade mesmo parada.
