---
name: chain-check
description: Validate facts or reasoning with the user as a numbered chain of short claims they confirm or correct. Use when you need the user to confirm something only they know, or when they ask to validate in a chain ("cadeia", "valida comigo").
---

Turn what needs validating into a **chain**: numbered **links**, each one short claim the user can confirm or reject at a glance. A stated claim is far easier to judge than an open question is to answer, so the chain does the remembering and the user only checks.

Write each link as one line holding one claim. When a link infers, put the **connective** in the line ("X, so Y", "Y because X"): reasoning breaks at connectives, and a connective on the page can be rejected. End a link you could not verify with `(?)`, or with a few words in parentheses when a source contradicts it.

Finding facts is your job, never the user's. Verify every link you can against the environment first; the chain carries only what the user alone can settle.

Work in **rounds**: one chain per round, three to eight links, starting with the chain the others rest on. A round is the chain alone; any context the user needs goes inside a link, in a few words. Format a round exactly like so, in the user's language:

```
**<conclusion the chain establishes>**

1. <claim>
2. <claim>, so <claim>
3. <claim> (?)

Reply ok, or the numbers that are wrong with the fix.
```

Apply the answer link by link. A confirmed link is settled. A wrong fact takes the user's version. A wrong connective comes out, leaving the facts on each side as plain statements unless the user gives the real cause. A correction that brings a new fact opens a new chain. Resend a chain only when a correction changed its conclusion.

The check is done when every link is confirmed or corrected. Act on the result only after that.
